1. Introduction                                           *project-config-intro*

`.nvim-project-settings.lua` is an optional, per-project settings file. It 
lives in a project's root directory and is read by this Neovim config to 
override per-project behavior.

If the file is absent, everything falls back to this config's built-in
defaults — nothing breaks or warns for a project that doesn't have one.

It is read by `lua/config/project.lua`, which every consuming plugin config
(`dap.lua`, `telescope.lua`, ...) calls into rather than reading the file
itself. See |nvim-config-adding| before adding a new direct `dofile()` call
anywhere else.

==============================================================================
2. File location                                       *project-config-location*

    <project-root>/.nvim-project-settings.lua

"Project root" is whatever `vim.fn.getcwd()` returns at the point the config
is read — the directory Neovim was opened in (or `:cd`'d to since). The file
must `return` a single Lua table; each top-level key is a *section*,
consumed independently by one part of the config.

Example: >lua
    return {
        dap = {
            ['<target-name>'] = {
                device    = '<target>',
                interface = 'swd',
                speed     = '4000',
                gdb_port  = 2331,
            },
            ['STM32L433CC'] = {
                device    = 'stm32l433cc',
                interface = 'swd',
                speed     = '4000',
                gdb_port  = 2331,
            },
        },
        telescope = {
            extra_dirs = { '../shared' },
            exclude = { },
        },
    }

Since it's a real `.lua` file evaluated with `dofile()`, it can contain any
valid Lua — computed values, conditionals, `os.getenv()`, etc. — not just a
static table. The last item on the table will show up first in the list.

==============================================================================
3. Sections                                            *project-config-sections*

------------------------------------------------------------------------------
dap                                                         *project-config-dap*

Overrides the debug target used by nvim-dap (`lua/plugins/dap.lua`). When
present, this REPLACES the preset picker entirely for this project — all
four fields are required.

    device      string  J-Link target device name (must match JLink's
                         device list)
    interface   string  'SWD' or 'JTAG'
    speed       string  Interface speed in kHz, as a string
    gdb_port    number  Port for JLinkGDBServer <-> the debug adapter

------------------------------------------------------------------------------
telescope                                             *project-config-telescope*

Adds extra search roots to Telescope's file/grep pickers (<leader>ff,
<leader>fa, <leader>fs, <leader>fp, <leader>fw), on top of the project root
— e.g. a sibling library that lives outside the project directory and would
otherwise need `../`, which also pulls in unwanted siblings.

    extra_dirs  string[]  Paths relative to the project root. Each is
                           resolved to an absolute path before use.

==============================================================================
4. Adding a new section                                  *project-config-adding*

To add a new per-project setting:

1. Pick a section name — a new top-level key in `.nvim-project-settings.lua`.
2. Read it with: >lua
    local cfg = require('config.project').section('my_section')
<
   `cfg` is `nil` if the file doesn't exist, doesn't have that key, or the
   key isn't a table — no need to re-check any of that yourself.
3. Document the section here, following the pattern above, and add it to
   |nvim-config-contents|.
